# Dashboard / Storage Explorer

Issue #22のモック確認を経て、既存のSwiftUI・Swift Charts・読み取り専用SQLite接続へ追加したViewer機能。監視周期、スキャン、監視設定、スキーマ、保持ルールを変更しない。

## 表示と操作

Dashboardの3カードは現在のSSD空き容量、24時間前からの容量増加、1時間前との容量増加。最新観測日時を右上、実際に比較した観測日時を比較カードの数値と同じ行に小さく表示する。使用量増加がプラス。24時間カードはStorage Explorerへ移動し、1時間カードのL3リンクは未提供。

L1は直近24時間の空き容量折れ線／空き容量増減棒を切替可能。単位はGiB、0:00の位置だけに縦点線を描く。空き容量増減棒のプラスは空き容量の増加であり、カード・L2の使用量増減とは符号が逆。

Storage ExplorerはB案の日本語名＋正式パス＋細い横棒。行で折れ線を追加・解除し、初期3系列・最大5系列。L1棒は別枠。現在容量はホバー、比較元・比較先日時はⓘで確認する。親子対象の値は重複するので合計しない。

子項目は件数の矢印から一覧内に展開し、検索・10件ずつのページ送り。検索結果数／全件数を入力欄右端に表示する。グラフをクリックして日付を選ぶと、親順位と子明細が同じ日に連動する。検索語・系列は維持し、子ページだけ先頭へ戻る。グラフとリストの小アイコンで双方向に移動できる。

右上メニューは「データを更新」「設定…」。既存の再読取・Widget再読込要求・保存先選択へ接続する。最小幅600pt。L2へは全体スクロールし、子明細はランキング枠内でスクロールする。

## 算出と欠測

- 最新の有効なL1は最新の監視対象パスに限定し、非負の`free`・エラーなし・現在時刻以前から選ぶ。最新行がエラーの場合も最後の有効値を使い、既存の鮮度／取得状態の注意を表示する。
- カードはその最新有効時刻の24時間前／60分前に最も近い有効L1を±90秒以内で選ぶ。同距離は過去側。`(比較元free − 最新free) / 2^30`を使用量増減とする。補間せず、候補なしはデータなし。
- L1グラフの差分は隣接観測の`free`差。境界直前1件も取得し、90秒超の間隔・NULL・エラーを跨いで棒を描かない。Widgetへ渡す既存24時間スナップショットの形式は変更しない。
- L2は`trigger=periodic`のみ。ローカル暦日ごとの最後の定期要求を代表とし、`started`（なければ`created`）を観測時刻とする。`scan_version=2`かつ`succeeded/partial`の完了観測だけから値を読む。
- 各日の代表と、その直前の暦日の代表を比較する。前日または当日の観測なし・失敗・実行中・skippedなら欠測。他の日の観測、manual、incidentで穴埋めしない。日付演算はCalendarを使い、夏時間でも7暦日固定。
- 一部取得のスキャンでも、両側が`status=ok`かつ非負bytes、同じ種類・同じ監視対象である行は比較可能。対象行の`partial/error/excluded/missing/NULL`や種類変更は「—」。深いエラー子孫を直下子として扱わない。
- 子は両観測の直下1階層の和集合。片側にない項目を0や削除と断定しない。比較不能理由はⓘで表示。
- L1棒はL2の同じ前日／当日代表時刻に最も近い有効L1（±90秒、同距離は過去側）を使い、同区間のfree差を使用量増減へ反転する。端点を照合できなければ棒なし。L2との差を一致させる処理や補間は行わない。
- 親一覧は最新の定期要求に保存された有効対象リストを使う。定期要求が未記録の場合のみ最後のL2記録の対象を表示する。監視設定ファイルを新たに探索せず、設定変更は次の監視記録後に反映する。

## 読み取りと保護

既存のbookmark・volume/inode照合・DB/sidecarのsymlink拒否を維持。接続は`SQLITE_OPEN_READONLY`、`query_only=ON`、短い読み取りトランザクション。同じスナップショットから最新値・比較値・L2を読む。SQLは対象パス・時刻・scan IDをbindし、UIに生のSQL/OSエラーを表示しない。

Widgetのキャッシュには従来のL1表示データだけを共有し、L2結果・対象パス・読み取り権限は共有しない。正式パスはViewer内の一覧／ホバーにのみ表示する。公開リポジトリに実測値や端末固有情報を含めない。

## 検証

- Python 3.11の既存テスト138件。
- `ViewerLogicChecks`：鮮度・遅延表示・Widget更新判定・欠測分断・軸日時。
- `StorageExplorerChecks`：L1の±90秒境界／同距離／符号／無効値、L2親子・片側欠測・部分取得・種類変更・v1除外、7暦日とDST、L1/L2対応、定期以外の除外。合成SQLiteでREADONLY・書き込み拒否・ファイル内容不変を検証。
- Xcode DebugのViewer＋Widgetビルド。実DBは読み取り専用で保存先照合・SELECTの動作確認のみ実施し、生レコードは出力しない。
- 本実装のViewerDetailを合成データで動かすGUIレビュー：600ptカード、5系列上限、子検索、グラフ選択と親子欠測連動、双方向ジャンプ、ウィンドウ拡大。
- 本番Widget内容の小・中サイズを5状態で合成データ描画。WidgetKitホストの長期稼働・再署名後の配置維持などは別の実機確認が必要。

検証の再実行（リポジトリルート）：

```sh
.venv/bin/python -m unittest discover -s tests -v
sh viewer/Tests/check-storage-explorer.sh
xcodebuild -project viewer/BlackboxViewer.xcodeproj -scheme BlackboxViewer -configuration Debug -derivedDataPath local/issue22/DerivedData build
```

GUIレビューは`StorageExplorerFixture.swift`と`StorageExplorerGUIReview.swift`を本番のApp/Sharedソース（Appの`@main`を除く）と一緒にコンパイルする。これらは本番Xcodeターゲットに含めない。

## 制約

L3詳細、Incident/L9連携、30日・過去7日間への移動は対象外。履歴不足や部分取得では表示できる値が限られる。L2はスキャン中の各項目の個別時刻を持たず、代表開始時刻を使用する。L1とL2は監視範囲・測定時間・APFSの特性が異なり、親合計とSSD変化は一致しない。
