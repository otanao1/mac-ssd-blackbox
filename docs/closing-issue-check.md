# Issue Close確認Skill

Related to [#27](https://github.com/otanao1/mac-ssd-blackbox/issues/27)。正本は対象Issueの本文と合意済みコメントです。

## 配置と利用

プロジェクト専用Skillは[`.agents/skills/closing-issue-check/SKILL.md`](../.agents/skills/closing-issue-check/SKILL.md)で管理します。Codexのリポジトリ内探索対象への配置であり、グローバル配布・共通版へのリンク・同期・新たな管理機構はありません。

このリポジトリを作業対象にして、`$closing-issue-check でIssue #Nの完了根拠と後片付けを確認してください`と呼び出します。完了判断・実機確認完了・「残件はない？」「後片付けは？」等でも利用する内容です。
配置仕様は[公式ドキュメント](https://learn.chatgpt.com/docs/build-skills)を参照。新しいセッションでの探索・自動選択と、ファイルを直接読んで使えることは別の確認として扱います。

| blackbox固有の調整 | 正式版と旧Viewer・モック、ビルド出力、プロセス、Launch Services・Widget登録を区別。登録先と実行中の実体を別々に確認し、既存のViewer開発メモと運用手順へ誘導。監視daemon・DB・現行設定と公開情報の安全条件を維持する。 |

参考ファイルは読み取りのみです。#22の整理は既に完了した事例として扱い、本実装では当時の削除・停止・登録解除を再実施しません。

## シナリオ確認

以下はSkillの文面を適用した机上確認です。実際の削除・プロセス停止・登録解除や、独立したエージェントによる実行試験ではありません。

| 想定する状態 | 確認・報告する結果 |
| --- | --- |
| #22相当：機能受入・Merge済み、Gitはclean、モック・ビルド出力・旧アプリ登録・Merge済みbranchが残る | 作業記録からGit外も確認。各対象を区分し、branchのMerge根拠と整理状況も示す。旧アプリのファイル・登録・実行実体を別々に扱い、機能受入だけで残件なしとしない。 |
| 正式版Viewerが稼働し、旧版を復旧用に保持する | 正式版を保護し、旧版は保持理由・ユーザー判断の有無を示す。削除を機械的に要求しない。 |
| 他Issueの成果物と由来不明の設定がある | 他Issueの対象は操作せず、不明な設定は判定不能として必要な確認を提示する。削除・停止・設定復元の許可と混同しない。 |
| 旧Widgetの登録先または実行実体を読み取れない | 未確認範囲・理由を明示する。登録なし・新版稼働・整理済みと断定せず、共有ホスト再起動へ進まない。 |
| squash mergeでローカルbranchの到達可能性が一致しない | 最新PRと比較先を照合。`git branch -d`が成立しないからと強制削除しない。 |
| 調査のみでPR・実機確認が不要 | 不要の理由と調査完了根拠・残存対象を確認。不要なPR・ビルド・実機操作を追加しない。 |
| 必要なPRが未Merge、または完了条件の根拠がない | 未完了として報告。Close可能とせず、SkillからCloseしない。 |

## 検証範囲と制約

- Skillを直接読み、既存の開発・運用ドキュメントとの整合を確認済み。RubyのYAMLパーサと一時的な検証コードでフロントマター・命名・ローカルリンク・空白・端末固有の絶対パス不在・リンクでない実ファイル配置を確認し、成功した。`git diff --check`と新規ファイルの空白チェックも成功。
- skill-creatorの`quick_validate.py`は既存Python環境にPyYAMLがないため実行できず、上記の形式検証で代替した。検証のためにグローバル環境やプロジェクトの依存関係は変更していない。
- この変更は指示文と利用案内のみ。監視エンジン・Viewerのコード変更やビルド、実データ調査は不要。
- 新セッションでの認識・明示呼び出し・読み取り確認は、下記のユーザー提供の実施報告により確認。自然文からの自動選択は未確認。
- 削除・停止・登録解除の試験は行っていない。読み取り確認と机上確認は、実際の後片付け操作の成功を保証しない。

## 別セッションでの利用確認

ユーザーから、新しいCodexセッションで#22を題材に確認した結果の提供を受けた。以下はその実施報告に基づく記録であり、実装セッションで同じ実機確認を再実施したものではない。

- 利用可能一覧にリポジトリ内のSkillが掲載され、`.agents/skills/closing-issue-check/SKILL.md`の実ファイルを読み込み、明示呼び出しから実際の読み取り確認まで実施できた。
- GitHubのIssue・PR・受入記録を照合し、過去の記録と現在状態、自動テスト・実機受入・今回未実施の検証を区別した。
- Git状態だけでなく、作業記録に基づくモック・ビルド出力、正式版アプリ、プロセス、アプリ・Widget拡張登録、設定を確認した。正式版の実行ファイル・読み込み実体を照合し、他Issueの対象へ操作を広げなかった。
- 既知の作業用出力と旧登録等は整理済み、レビュー用成果物と正式版は理由があって保持と整理した。一方、全仮配置先や一時設定の由来等は判定不能・未確認として報告し、端末上の残存物が完全にゼロとは断定しなかった。
- 残存物がある場合の「対応待ち」等の判断は机上確認として補足し、現在の実機確認と分けた。
- 削除・停止・登録解除・設定変更・Issue編集／Close・commit・push・PR作成は実施せず、BodyMap・home-labも変更していないとの報告。確認前後のGit状態は同じだった。

この結果から、認識・明示利用・読み取り確認・安全条件について修正が必要な問題は報告されていない。自然文からの自動選択、実画面の再受入、長期安定性、削除等の操作は未検証。実機の未確認範囲を適切に残したことは、Skillの確認失敗や削除操作の必要性を意味しない。
