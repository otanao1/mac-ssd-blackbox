# Blackbox Viewer

## 概要

Blackbox Viewerは、Macの内蔵SSDの空き容量を日常的に確認し、過去24時間にどう変化したかを振り返るためのmacOSアプリです。Dashboardの比較カードと、ディレクトリ別の増減を確認するStorage Explorer（L2／L3、Single／Multi）を備えます。
mac-ssd-blackboxの監視エンジンが記録した空き容量（L1履歴）を使い、詳細画面・メニューバー・デスクトップWidgetの3か所で表示します。

普段はメニューバーやWidgetで空き容量を確認し、気になる変化があれば詳細Viewerでグラフを見られます。
Viewerは監視エンジンとは独立したアプリです。利用するには、先に[監視エンジンのセットアップ](../docs/operations.md)を行い、履歴を記録しておく必要があります。

## 主な機能

| 表示場所 | できること |
| --- | --- |
| 詳細Viewer | 大きな数値で空き容量を確認し、直近24時間のグラフで増減の時刻や規模を振り返れます。表示期間と最終観測時刻も確認できます。 |
| メニューバー | ディスクアイコンの横に空き容量（GiB）を表示します。ウィンドウを閉じていても値を確認でき、メニューからViewerを開けます。 |
| デスクトップWidget | 小・中サイズのグラフと空き容量をデスクトップに表示します。左下の時計の横に最終観測時刻があり、クリックすると詳細Viewerを開けます。 |

Dashboardのグラフは空き容量の折れ線／前回観測との差分棒を切り替えます。時刻は3時間ごと、日付が変わる0:00だけに縦点線を表示します。
表示時刻はMacのローカル時刻です。「最終観測」の `HH:mm` は現在時刻ではなく、監視エンジンが容量を記録した時刻です。

## 動作環境

- macOS 14以降。
- macOS向け開発環境を導入したXcodeと、署名に使用するApple Account／Team。
- セットアップ済みの監視エンジン、その設定ファイル `local.json`、対応する `blackbox.sqlite3` を含む保存フォルダ。
- 監視データの保存先は内蔵ディスクまたは外付けSSD。ViewerはNAS保存先に対応していません。

現在はXcodeからビルドして使用します。無料のPersonal Teamによる実機利用を確認していますが、すべての署名環境やmacOS 14以降の全環境で動作確認済みではありません。
確認した環境と未検証項目は[開発メモの検証範囲](../docs/project-development-viewer-notes.md#検証範囲)を参照してください。

## インストール・起動

1. プロジェクトをGitHubから取得し、Xcodeの初期セットアップを完了します。Viewer用にiOS等のSimulatorを追加する必要はありません。
2. XcodeのAccountsにApple Accountを登録し、`viewer/BlackboxViewer.xcodeproj` を開きます。
3. Git管理外の `viewer/Local.xcconfig` に、自分のTeamを指定します。既存ファイルがある場合は内容を確認して使用してください。

   ```xcconfig
   DEVELOPMENT_TEAM = YOUR_TEAM_ID
   CODE_SIGN_IDENTITY = Apple Development
   REGISTER_APP_GROUPS = NO
   ```

4. `BlackboxViewer` と `BlackboxWidget` の両ターゲットで、同じTeamとApp Group（ViewerとWidgetのデータ共有先）を使うことを確認します。
   共通設定がTeamに応じたApp Groupを指定します。設定の詳細は[Personal TeamとApp Group](../docs/project-development-viewer-notes.md#personal-teamとapp-group)を参照してください。
5. スキームを `BlackboxViewer`、実行先をMacにしてビルド・実行します。起動後、次の初期設定を行います。

上記はPersonal Teamで確認した設定方法です。ad-hoc署名だけでの動作は前提にしていません。
Widgetの共有先を利用できない場合は警告を表示し、別の任意の場所へデータを保存しません。

ビルド前後に内蔵SSDの空き容量を確認してください。容量が少ない場合はXcodeのビルド用保存先（DerivedData）を空きのある外付けSSDへ配置します。初回セットアップやビルドに必要な空き容量の固定値は確定していません。
ビルドしたアプリは一定の場所で使用し、古いビルドとの重複登録を避けてください。起動するとDockにもアイコンが表示されます。

## 初期設定

### 監視データの保存先を選ぶ

1. 監視エンジンでL1履歴が記録されていることを確認します。
2. Viewerの「保存先を設定…」を押し、既存監視の設定ファイル `local.json` を選択します。
3. 続いて、その監視の `blackbox.sqlite3` がある保存フォルダを選択します。ファイル単体ではなくフォルダを選びます。
4. 空き容量のグラフと最終観測時刻が表示されることを確認します。

設定ファイルと保存フォルダは、同じ監視の組み合わせである必要があります。監視設定の識別値を手で書き換えないでください。
選択はViewer内に保持され、次回起動でも使用します。

### デスクトップにWidgetを追加する

デスクトップを右クリックし、「ウィジェットを編集」からBlackbox Viewerの「SSD空き容量」を追加します。
小・中サイズを選べます。WidgetにはViewerが取得したデータが表示されるため、利用中はViewerを起動しておきます。

## 使い方

| 操作 | 動作 |
| --- | --- |
| 詳細画面の更新アイコンを押す | データを再取得し、Widgetにも表示更新を要求します。 |
| Viewerのウィンドウを閉じる | メニューバーに常駐し、データ更新を継続します。 |
| メニューバーの「Viewerを開く」 | 詳細画面を再表示します。 |
| メニューバーの「設定…」／詳細画面右下の「設定」 | 既存の保存先選択を開きます。 |
| メニューバーの「終了」 | Viewerと表示データの更新を終了します。監視エンジンは停止しません。 |
| Widgetをクリック | ViewerのL1詳細画面を開きます。 |

メニューバーの項目は「Viewerを開く」「設定…」「終了」の3つです。
ログイン時の自動起動はありません。Macへのログイン後など、必要なときにViewerを起動してください。

### DashboardとStorage Explorer

- 上部カードはSSD空き容量、1時間前、24時間前からの使用量増減の順。L1／L3／L2へそれぞれ移動し、各セクションからDashboardへ戻れます。カードの比較元は有効L1の±90秒以内で、フォルダ容量の合計ではありません。
- 3段は「SSD空き容量」「フォルダ使用量（特定アプリ）」「フォルダ使用量（全体）」。初期表示はL3がSingle・容量・3日、L2がMulti・差分・7日です。
- L2は7日・30日、L3は24時間・3日・7日・30日を選べます。期間変更は終了日時を維持し、前後移動は選択中の期間単位です。最新を超えず、「最新へ」で直近に戻ります。
- Single／Multiは対象数、容量／差分は表示値の切替です。グラフ右上の相互矢印ボタンは切替先（容量表示中は「差分」、差分表示中は「容量」）を示します。切替で対象・系列・階層・選択観測は変えません。
- Singleは選択対象の容量または差分の推移と、選択観測時点のサブフォルダを表示。記録済みの子を開き、親・パンくずで戻れます。未記録階層は追加取得せず「サブフォルダ記録なし」と表示します。partialの容量は取得済み範囲です。
- Multiは増減ランキング、初期3／最大5系列、子展開・検索・10件単位のページ送り、SSD使用量増減棒を維持。グラフで観測を選ぶと親子一覧も連動します。親子の値は合算しません。
- 通常比較は実線、失敗領域が一致する参考比較は薄い実線、比較不可の前後を結ぶ補助線は細かい点線。正常取得は丸、一部取得は中抜き菱形です。補助線の途中に増減値はありません。未取得領域内部の増減も不明です。
- L3は毎時生履歴だけを読みます。保持期間外・欠測はデータなしとし、日次集約やmanual／incidentで補いません。L2は従来の前暦日、L3は前の1時間枠の定期代表と比較します。
- 切替・更新時は可能な限り選択を保持します。右上の既存メニューに「初期表示に戻す」を追加し、モード・容量／差分・期間・対象・系列・階層・検索等を初期化して最新へ戻します。アプリ再起動時は初期表示です。保存先設定は別途従来どおり保持します。
- 詳しい算出・欠測規則、検証範囲は[Storage Explorerの説明](../docs/storage-explorer-viewer.md)を参照してください。

### 今日の状況

Viewer上部の「今日の状況」で独立画面を開き、「Dashboardへ」で戻ります。初期表示は今日。右上の前日／翌日で1日ずつ移動でき、未来には進みません。

- SSD使用量増減カードは選択日の最初・最後の有効L1観測による増減と前後使用量を表示。ⓘで計算元の日時を確認できます。比較元がない日や欠測は値を推測しません。
- ScanカードはL2/L3/L9の総実行回数と、定期／Incident・階層別の内訳。共有Scanは1回として集計し、L1や未開始要求は含めません。
- Incidentカードは総数・原因特定（緑）／原因未特定（グレー）／一次調査中（青）・未特定A〜Dの内訳。「未特定の内訳」で分類を確認できます。旧記録の分類根拠がない場合はその旨を表示します。
- 下段の全幅タブでIncident一覧／Scan一覧を切り替えます。Incidentは新しい検知順、Scanは新しい実行順。Scan行を展開すると保存済みの対象・容量・実行状態・失敗等を確認できます。
- 原因特定の増加量と、未特定の参考増加情報は表示を区別します。赤い数値はSSD空き容量の減少量。Incident減少量比は因果関係の説明率ではありません。
- 日付を変えるとカードと両一覧が切り替わり、Scan展開を初期化します。タブ選択は維持します。更新時の取得失敗は記録なしと区別して表示します。

通常履歴の保持期限後もIncidentに残る証跡を表示します。Scan明細は保存結果の先頭100件（失敗優先・容量降順）と総件数を表示します。新規Scanや監視操作は行いません。詳しくは[表示・算出規則](../docs/today-viewer.md)を参照してください。

### 表示に困ったとき

| 状況 | 最初に確認すること |
| --- | --- |
| 保存先を確認できない／取得失敗 | 外付けSSDの接続と、設定ファイル・保存フォルダの組み合わせを確認します。保存先の移設・DB再作成・アクセス許可の失効時は選び直します。 |
| Widget共有を利用できない | 両ターゲットのTeam・App Groupが一致するか確認します。 |
| Widgetの値が古い | Viewerが起動中か、最終観測時刻が進んでいるかを確認し、Viewerで手動更新します。WidgetKitによる表示遅延もあります。 |
| Widgetのデザインだけ旧版 | [旧Widgetの切り分け手順](../docs/project-development-viewer-notes.md#widgetが旧版のまま表示される場合)を参照します。 |
| Dockのアイコンだけ旧版 | [アイコンの反映手順](../docs/project-development-viewer-notes.md#dockのアプリアイコンが更新されない場合)を参照します。 |

## 動作上の制約

### 更新と古い値の表示

Viewerは起動時・起動中の約60秒間隔・スリープ復帰・手動操作で更新します。ウィンドウを閉じても更新しますが、Viewerの終了後は新しい表示データを取得しません。
OSによる休止やスリープ中の毎分実行は保証しません。別の常駐ヘルパーはありません。

Widgetには新しい観測や状態変更の取得後、または手動更新時に表示更新を要求します。
Widget自身の通常の更新希望時刻は15分後ですが、実際の反映はmacOSのWidgetKitが管理します。即時反映・毎分更新は保証しません。

最終観測が180秒超前の値は現在値として扱いません。Widgetの「表示更新待ち・前回の観測値」は、監視データの取得失敗やViewer終了とは異なる表示です。
通常終了時には終了状態を記録しますが、Widgetへの即時反映は保証しません。異常終了時も最終観測時刻で古さを判定します。

### グラフと取得失敗

- 空き容量は監視が記録した `free` をGiB表示します（`available` ではありません）。最新の監視対象について直近24時間を表示します。
- 取得エラー・値の欠落・90秒超の観測間隔では線をつながず、孤立した観測は点で表示します。欠測区間を補間して隠しません。
- 外付け切断・DBの置換・他の処理との読み取り競合などで取得できない場合は、詳細画面に失敗を表示し、メニューバーの数値を `—` にします。前回の履歴があれば詳細画面・Widgetに残します。
- L2／L3の容量・増減と、監視側が保存したIncident一次調査結果を表示します。Viewer自身は原因を再判定しません。監視エンジンの開始・停止は行いません。

### データの保護

監視データは読み取り専用で参照します。既存の監視設定・データの構造・監視周期・保持ルールを変更せず、新規スキャンやDBの修復も行いません。
設定と異なる保存先や置き換わったDBをそのまま使わないよう照合します。DB再作成・移設・保存先の識別情報更新・アクセス許可の失効時は、対応する設定とフォルダを選び直してください。

保存先情報と読み取り用のアクセス許可はViewer内だけに保持します。Widgetには表示に必要な観測値・時刻・状態を共有し、監視DBへ直接アクセスさせません。
正式パスはViewer内の一覧・ホバーに表示します。Widgetや共有キャッシュへ対象パスを渡さず、生のエラー文字列は画面・Widgetに表示しません。監視DB・履歴・表示キャッシュ・個人署名設定を公開リポジトリへ追加しないでください。
