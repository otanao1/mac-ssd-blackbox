## 構成

- `BlackboxViewer.xcodeproj`: アプリと埋め込みWidget拡張の2ターゲット。
- `App`: アプリ所有の更新モデル、読み取り専用SQLite接続、設定選択、詳細ViewerとMenuBarExtra。
- `Shared`: パスを含まない表示モデル、24時間グラフ、App Group内の原子的なJSONキャッシュ。
- `Widget`: キャッシュのみ読むTimelineProvider。元DBや監視CLIへアクセスしません。

メニューバーは `SSD 3.10 GiB` のように表示します。メニューは「Viewerを開く」「終了」のみ。
ウィンドウを閉じてもアプリ所有の更新処理を続けます。「終了」でプロセスと更新を停止します。
ログイン時の自動起動は今回追加しません。Dockアイコンのある通常のmacOSアプリです。

## データと安全条件

詳細画面の「保存先を設定…」で、既存監視の `local.json` と対応するDB保存フォルダを順に選択します。
設定・監視DBは変更しません。識別情報と読み取り専用security-scoped bookmarkはViewerのコンテナ内にのみ保存します。
ボリュームUUID・ディレクトリinode・DB inode・保存先パスを照合し、シンボリックリンクへの置換を拒否します。
この試作は設定の `storage.volume.kind == disk` に対応し、NASは対象外です。
DB再作成・移設・識別情報更新・bookmark失効時は、設定とフォルダの選択をやり直します。

SQLiteは `SQLITE_OPEN_READONLY` と接続単位の `query_only` を使用。短い読み取りトランザクションで
直近24時間と最新観測を取得し、すぐ閉じます。待機は100msまでです。既存Store/CLIは起動しません。
`immutable`、ロック無効化、WAL切替、スキーマ変更、DBコピー、新規スキャンは行いません。
現在のDELETE journal方式でリカバリーが必要な場合もViewerが書き込んで復旧せず、取得失敗を表示します。

L1の `free` をGiB表示し、`available` へ置換しません。最新の監視対象パスで系列を分離します。
取得エラー・NULL・150秒超の欠測では線をつなぎません。最新観測が180秒超前なら現在値と扱いません。
外付け切断・DB置換・ロック競合時はメニューバーを `SSD —` とし、詳細画面は取得失敗を表示します。
前回の履歴があれば詳細画面・Widgetには「前回値」として残します。実パス・生エラーは画面・Widgetに出しません。

起動時・起動中の約60秒間隔・スリープ復帰・手動操作で更新します。OSによる休止やスリープ中の毎分実行は保証しません。
Widgetへの再読込要求は状態変更時と最大約15分間隔で行い、実際の反映はWidgetKit管理です。
キャッシュの最終観測時刻から古さを判定するため、アプリ終了・異常終了時も現在値として表示し続けません。
通常終了時はキャッシュにも終了状態を記録しますが、Widgetの即時反映は保証しません。
