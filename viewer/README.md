# Blackbox Viewer prototype (#19)

SwiftUI + Swift Charts + WidgetKit, macOS 14以降。Python監視エンジンとは別のアプリで、常駐ヘルパーは追加しません。

## 現在の状態

2026-10-24、Xcode 27.0でmacOS arm64のDebugビルドとPersonal Teamによる署名に成功しました。
Viewer・埋め込みWidget拡張の署名検証、Viewerでの実L1グラフ表示、App Group表示キャッシュへの保存を確認済みです。
初版のメニューバー操作、Widgetの値・グラフ表示とViewerへの遷移はユーザー確認済みです。
ウィンドウを閉じた64秒間に、表示キャッシュとL1観測時刻が約60秒進むことを確認しました。
メニューバーの「終了」をユーザーが選択した後、プロセス消滅とキャッシュの `stopped` 状態を確認しました。
再起動後も保存先の再選択なしで実データを表示でき、読み取り専用bookmarkの保持を確認済みです。
長時間稼働・更新間隔・障害系すべてを検証したという意味ではありません。
署名の個人設定とビルド記録・成果物はGit管理外に保持しています。
DerivedDataは外付けSSDに配置し、ビルド時のSwiftコード修正は不要でした。
未確認事項はWidgetの全サイズ・長時間の更新挙動、外付け切断・置換、bookmark失効、ロック競合等です。

## 構成

- `BlackboxViewer.xcodeproj`: アプリと埋め込みWidget拡張の2ターゲット。
- `App`: アプリ所有の更新モデル、読み取り専用SQLite接続、設定選択、詳細ViewerとMenuBarExtra。
- `Shared`: パスを含まない表示モデル、24時間グラフ、App Group内の原子的なJSONキャッシュ。
- `Widget`: キャッシュのみ読むTimelineProvider。元DBや監視CLIへアクセスしません。

メニューバーはディスクアイコンと `3.10 GiB` をRegular・等幅数字で表示します。
メニューは「Viewerを開く」「設定…」「終了」の3項目で、「設定…」は既存の保存先選択を開きます。
ウィンドウを閉じてもアプリ所有の更新処理を続けます。「終了」でプロセスと更新を停止します。
ログイン時の自動起動は今回追加しません。Dockアイコンのある通常のmacOSアプリです。

## データと安全条件

詳細画面の「保存先を設定…」で、既存監視の `local.json` と対応するDB保存フォルダを順に選択します。
設定・監視DBは変更しません。識別情報と読み取り専用security-scoped bookmarkはViewerのコンテナ内にのみ保存します。
ボリュームUUID・ディレクトリinode・DB inode・保存先パスを照合し、シンボリックリンクへの置換を拒否します。
この試作は設定の `storage.volume.kind == disk` に対応し、NASは対象外です。
DB再作成・移設・識別情報更新・bookmark失効時は、設定とフォルダの選択をやり直します。

SQLiteは `SQLITE_OPEN_READONLY` と接続単位の `query_only` を使用。短い読み取りトランザクションで
直近24時間と最新観測を取得し、すぐ閉じます。待機は100msまでです。既存Store/CLIは起動しません。
`immutable`、ロック無効化、WAL切替、スキーマ変更、DBコピー、新規スキャンは行いません。
現在のDELETE journal方式でリカバリーが必要な場合もViewerが書き込んで復旧せず、取得失敗を表示します。

L1の `free` をGiB表示し、`available` へ置換しません。最新の監視対象パスで系列を分離します。
取得エラー・NULL・90秒超の観測間隔では線をつなぎません（毎分観測の遅れを30秒まで許容）。
最新観測が180秒超前なら現在値と扱いません。
外付け切断・DB置換・ロック競合時はメニューバーを `SSD —` とし、詳細画面は取得失敗を表示します。
前回の履歴があれば詳細画面・Widgetには「前回値」として残します。実パス・生エラーは画面・Widgetに出しません。

起動時・起動中の約60秒間隔・スリープ復帰・手動操作で更新します。OSによる休止やスリープ中の毎分実行は保証しません。
Widgetへの再読込要求は新しい観測・状態変更を原子的に保存した直後に行います。手動更新でも要求します。
同じ観測・状態の再保存だけでは要求せず、Widget自身の通常の更新希望時刻は15分後としています。
要求が即時反映される保証はなく、実際の反映はWidgetKit管理です。
キャッシュの最終観測時刻から古さを判定するため、アプリ終了・異常終了時も現在値として表示し続けません。
通常終了時はキャッシュにも終了状態を記録しますが、Widgetの即時反映は保証しません。

## 署名・ビルド設定

`Config.xcconfig` のApp GroupはmacOSの `<Team ID>.io.github.otanao1.blackbox-viewer` 形式を使います。
Git管理する設定ではTeamを固定していません。今回の実機試作はユーザー承認済みのPersonal Teamを使用しています。
両ターゲットは同じTeam・Groupを使う必要があります。App Group権限を使うためad-hoc署名のみでの動作は前提にしません。
個人のTeam等を保存する場合はGit管理外の `Local.xcconfig` を使います。
今回のローカル設定は両ターゲット共通の `DEVELOPMENT_TEAM`、`CODE_SIGN_IDENTITY = Apple Development`、
`REGISTER_APP_GROUPS = NO` を指定し、Team ID形式のApp Groupを使用しています。
共有先を利用できない場合、Viewerは警告を表示し、任意の代替パスへ保存しません。

容量確保後にプロジェクトを開き、DerivedData・ビルド成果物の保存先を十分な空きのある外付けSSDへ指定します。
macOS実機だけを対象にし、不要なSimulator・プラットフォームを追加しないでください。
実機確認時は同じビルドのアプリを一定の場所に配置してWidgetを登録し、古いビルドとの重複登録を避けてください。

## UIレビュー改修と調査（2026-10-24）

- 詳細画面は上部の薄い背景の横長カードに「内蔵SSD 空き容量」と大きな数値・小さな単位を配置します。
  グラフタイトルは「時系列推移（24時間）」、同じ行の右側に最終観測 `HH:mm` と更新アイコンを置きます。
  表示期間 `MM/dd ～ MM/dd` と右上の `[GiB]` はグラフ上部に表示します。
  3時間軸と0始まりのY軸を維持し、0:00は通常の点線より少し太い実線です。
  縦の補助線はRuleMarkで描画領域内に限定し、軸ラベルは時刻のみ、端では内側へ寄せて欠けを防ぎます。
  下部は小さな「設定」のみとし、常駐の説明は通常画面から外しています。標準タイトルバーは変更しません。
- Widget最終レイアウトは小・中共通で上部にオレンジの24時間グラフ、左下に時計アイコンとL1観測時刻 `HH:mm`、
  右下に大きな容量と小さな `GiB` を配置します。見出しは表示しません。
  小サイズの容量は24pt、中サイズは32ptを基準に必要時のみ縮小します。
  古い表示・取得失敗の説明はグラフと下段の間に残します。
  メニューバーでは `Label` がアイコンのみになったため明示的な横並びへ修正し、アイコン＋数値＋単位の表示をユーザー確認済みです。
- Widget旧実装は3分後に古い表示と判定する一方、再読み込み要求を15分抑制していました。
  健全な共有キャッシュがあっても古いタイムラインが警告を出すため、新しい観測で抑制せず要求するよう修正しました。
  表示が古い場合は「表示更新待ち・前回の観測値」とし、DB取得失敗・Viewer終了とは区別します。
- 調査時の直近24時間のL1は取得エラー0件、150秒超の間隔7か所でした。これらは実際の観測間隔であり、
  分断を維持します。さらに100〜147秒空いた4区間が旧表示ではつながっていたため、毎分観測に対する
  表示側の許容を90秒までとし、計11か所を分断します。監視の周期・設定は変えません。
  1点しかない区間も見えるよう点を描き、欠測をまたいで線をつなぎません。
- 同じ表示キャッシュで直線と単調三次補間の比較画像を生成しました。24時間表示での差は小さく、
  急変の形を変える利点は確認できないため、採用方式は直線を維持しています。補間変更の最終判断は画面レビューに回します。
- `Tests/ViewerLogicChecks.swift` はDBを使わず、古いタイムラインの文言、新しい観測での再読み込み判定、
  NULL・欠測の区間分離と90秒境界、期間境界、3時間軸と日付・夏時間、年初の日時表記を確認します。
  `Tests/RenderChartComparison.swift` は表示キャッシュから比較PNGを作るローカル確認用です。
  いずれもアプリ・Widgetターゲットには含めず、出力はGit管理外の外付け領域へ置きます。
- `Tests/RenderWidgetLayout.swift` は `-D WIDGET_LAYOUT_CHECK` で本番Widgetの内容と一緒にコンパイルする
  ローカル画像確認用です。小164×164pt・中344×164ptで、通常・3桁容量・古い表示・取得失敗・未設定の

## Widget新版が反映されない場合の確認

2026-10-24の実機では、登録された拡張のパスは正しい一方、Widgetプロセスが再ビルド前の実行ファイルと
debug dylibを保持していました。読み込み済みファイルとディスク上の成果物のinodeが異なり、
表示データだけ更新されても旧レイアウトで描画される状態でした。共有キャッシュの不具合とは分けて扱います。

当該拡張だけを通常終了してViewerから再読み込みを要求した後、新プロセスと成果物のinode一致を確認し、
ユーザーもオレンジ・時計アイコン・見出しなしの新レイアウトへの切り替わりを確認しました。
当該確認時のアプリ・Widget共通のビルド番号は2でした（アイコン追加後は3）。ビルド番号の更新だけで既存プロセスの置換を保証するものではありません。

次回も反映しない場合は、起動中Viewerの実体、Widgetの登録先、読み込み済み拡張の実体を先に照合します。
所属を確認できた旧拡張のみを通常終了し、同じ成果物のViewerを起動して更新します。
必要なら当該Blackbox Widgetだけを削除し、デスクトップの「ウィジェットを編集」から再追加します。
他アプリのWidget・Notification Center・Dock全体の設定初期化は行いません。

追加Viewer改善では署名付きビルド・署名検証・実機表示を確認し、600pt幅の端点ケースでも
時刻ラベルの欠けと補助線のはみ出しがないことをローカル描画で確認しました。
