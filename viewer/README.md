# Blackbox Viewer

既存のmac-ssd-blackboxが記録したL1空き容量を表示する、独立したmacOSアプリの試作です。
SwiftUI・Swift Charts・WidgetKitを使用します。監視エンジンのインストールや起動は行いません。

## 機能

- 詳細Viewer：現在の空き容量と直近24時間の推移。0始まりのY軸、3時間ごとの時刻、日付変更位置、表示期間を表示します。
- メニューバー：ディスクアイコンと空き容量（GiB）を表示します。
- デスクトップWidget：小・中サイズに対応。上部にオレンジのグラフ、左下に時計と最終観測時刻、右下に空き容量を表示します。
- Widgetのクリックで詳細Viewerを開けます。

表示時刻はMacのローカル時刻です。最終観測の `HH:mm` は現在時刻ではなく、L1の観測時刻です。
L3可視化や監視の開始・停止などは対象外です。背景・実装範囲は[Issue #19](https://github.com/otanao1/mac-ssd-blackbox/issues/19)を参照してください。

## 動作環境

- macOS 14以降。
- macOS向け開発環境を導入したXcodeと、署名に使用するApple Account／Team。
- セットアップ済みの[監視エンジン](../docs/operations.md)、その `local.json`、対応する `blackbox.sqlite3` を含む保存フォルダ。
- 保存先は内蔵ディスクまたは外付けSSD（`storage.volume.kind == disk`）。このViewer試作ではNASに対応していません。

現在はXcodeからソースをビルドして使用します。検証済みの環境・未検証項目は[開発メモの検証範囲](../docs/project-development-viewer-notes.md#検証範囲)を参照してください。macOS 14以降のすべての環境で実機検証済みという意味ではありません。

## ビルドと署名設定

1. Xcodeの初期セットアップを完了し、AccountsにApple Accountを登録します。Viewer用にiOS等のSimulatorを追加する必要はありません。
2. `viewer/BlackboxViewer.xcodeproj` を開きます。
3. Git管理外の `viewer/Local.xcconfig` を作成し、利用するTeamを指定します。既存ファイルがある場合は内容を確認して使用してください。

   ```xcconfig
   DEVELOPMENT_TEAM = YOUR_TEAM_ID
   CODE_SIGN_IDENTITY = Apple Development
   REGISTER_APP_GROUPS = NO
   ```

4. `BlackboxViewer` と `BlackboxWidget` の両ターゲットで同じTeam・App Groupを使用することを確認します。Team IDは自分の値に置き換えてください。
   共通の `Config.xcconfig` は `Local.xcconfig` を読み込み、App Groupを `$(DEVELOPMENT_TEAM).io.github.otanao1.blackbox-viewer` に展開します。
   この設定はPersonal Teamによる実機試作で確認した方法です。別環境での成立を保証するものではありません。
5. スキーム `BlackboxViewer`、実行先をMacにしてビルド・実行します。

App Group権限を使うため、ad-hoc署名だけでの動作は前提にしていません。共有先を利用できない場合は警告を表示し、別の任意パスへ保存しません。
署名設定の補足は[Personal TeamとApp Group](../docs/project-development-viewer-notes.md#personal-teamとapp-group)を参照してください。

ビルド前後に内蔵SSDの空き容量を確認してください。容量が少ない場合はXcodeのDerivedDataを空きのある外付けSSDへ配置します。初回セットアップやビルドに必要な空き容量の固定値は、この試作では確定していません。
同じ成果物のアプリを一定の場所で使用し、古いビルドとの重複登録を避けてください。

## 初回設定と基本操作

1. 先に監視エンジンをセットアップし、L1履歴が記録されていることを確認します。
2. Viewerを起動し、「保存先を設定…」から既存監視の `local.json` を選択します。
3. 続いて、同じ監視の `blackbox.sqlite3` がある保存フォルダを選択します。DBファイル単体ではなくフォルダを選びます。
   設定と実際の保存先の識別情報が一致する必要があります。監視設定の識別値を手で書き換えないでください。
4. グラフと最終観測時刻を確認します。グラフタイトル右の更新アイコンで手動更新できます。
5. デスクトップを右クリックし、「ウィジェットを編集」からBlackbox Viewerの「SSD空き容量」を追加します。小・中サイズを利用できます。

| 操作 | 動作 |
| --- | --- |
| Viewerのウィンドウを閉じる | メニューバーに常駐し、データ更新を継続します。 |
| メニューバーの「Viewerを開く」 | 詳細画面を再表示します。 |
| メニューバーの「設定…」／詳細画面右下の「設定」 | 既存の保存先選択を開きます。 |
| メニューバーの「終了」 | Viewerと表示データの更新を終了します。監視エンジンは停止しません。 |
| Widgetをクリック | ViewerのL1詳細画面を開きます。 |

保存先の選択はViewer内に保持され、次回起動で使用します。ログイン時の自動起動や追加の常駐ヘルパーはありません。Dockアイコンを持つ通常のmacOSアプリです。

## データの取り扱いと制約

### 監視データへのアクセス

Viewerだけが既存SQLiteを読み取り専用で参照します。監視エンジン・既存設定・DBスキーマ・監視周期・保持ルールを変更せず、新規スキャンも実行しません。
保存先の識別情報と読み取り専用security-scoped bookmarkはViewerのコンテナ内に保存し、Widgetへ渡しません。
ボリュームUUID、フォルダ・DBのinode、保存先パスを照合し、シンボリックリンクへの置換を拒否します。
DB再作成・移設・識別情報更新・bookmark失効時は、対応する設定と保存フォルダを選び直してください。

WidgetはApp Group内の表示用JSONのみを読みます。元DBや監視CLIへ直接アクセスしません。
共有データには観測値・時刻・状態を含め、監視の実パスは含めません。実パスや生のエラー文字列を画面・Widgetに表示しません。
監視DB・履歴・表示キャッシュ・個人署名設定を公開リポジトリへ追加しないでください。

### グラフと取得失敗

- L1の `free` をGiB表示します（`available` ではありません）。最新の監視対象パスの系列を表示します。
- 折れ線は直線です。取得エラー・NULL・90秒超の観測間隔ではつながず、孤立した観測は点で表示します。欠測を補間して隠しません。
- 最終観測が180秒超前の値は現在値として扱いません。
- 外付け切断・DB置換・ロック競合などの取得失敗時は、詳細画面に失敗を表示し、メニューバーの数値を `—` にします。前回の履歴があれば詳細画面・Widgetに残します。
- DBの復旧が必要な場合もViewerが書き込んで修復することはありません。

### 更新タイミング

Viewerは起動時・起動中の約60秒間隔・スリープ復帰・手動操作で更新します。OSによる休止やスリープ中の毎分実行は保証しません。
ウィンドウを閉じても更新しますが、Viewerプロセスの終了後は新しい表示データを取得しません。

新しい観測・状態変更を共有キャッシュへ保存した後、Widgetの再読み込みを要求します。手動更新でも要求します。
Widget自身の通常の更新希望時刻は15分後です。即時反映・毎分更新は保証せず、実際のタイミングはWidgetKitが管理します。
表示が古い場合の「表示更新待ち・前回の観測値」は、DB取得失敗やViewer終了の表示とは異なります。
通常終了時は終了状態をキャッシュに記録しますが、Widgetへの即時反映は保証しません。異常終了時も最終観測時刻によって古さを判定します。

## トラブルシューティング

| 状況 | 最初に確認すること |
| --- | --- |
| 保存先を確認できない／取得失敗 | 外付けSSDの接続、選択した設定とDBフォルダの対応を確認します。DB再作成やbookmark失効時は選び直します。 |
| Widget共有を利用できない | 両ターゲットのTeam・App Groupが一致するか確認します。 |
| Widgetの値が古い | Viewerが起動中か、L1最終観測が進んでいるかを確認し、Viewerで手動更新します。WidgetKitによる表示遅延もあります。 |
| Widgetのデザインだけ旧版 | [旧Widgetの切り分け手順](../docs/project-development-viewer-notes.md#widgetが旧版のまま表示される場合)を参照します。 |
| Dockのアイコンだけ旧版 | [アイコンの反映手順](../docs/project-development-viewer-notes.md#dockのアプリアイコンが更新されない場合)を参照します。 |

内部構成、検証方法、既知の制約の補足は[Viewer開発メモ](../docs/project-development-viewer-notes.md)にまとめています。
