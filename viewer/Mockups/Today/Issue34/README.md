## 操作・確認点

- 初期表示はIncident一覧。全幅タブでScan一覧へ切り替える。
- 上部は左にSSD使用量増減／Scanの2カード、右にIncidentカード。「未特定の内訳」でA〜Dの説明をポップアップ表示。閉じるボタン・Escape・外側クリックで閉じる。
- SSD使用量増減は大きな増減量の真下に前後使用量を左揃えで表示。ⓘへのホバー・フォーカス・クリックで、計算に使用した最初／最後のL1観測日時を表示する。観測日時の常設説明文は置かない。欠測時は前後値を推測しない。
- Scanカードは総実行回数と起因別／L2・L3・L9別の内訳を2行にまとめる。実際の一覧データをIDで重複排除し、L1を除外して集計する。共有Scanの集計説明文はカードから削除。
- Incidentサマリーの状態別件数は横3列の薄い境界線付きサブカード。数字・アイコンは一覧と共通の緑／グレー／青、ラベルは小さなグレー。総数・A〜D内訳は維持。
- Incidentは新しい順に、一次調査中、原因特定2件、原因未特定A〜Dの計7件。関連Scan行はクリックまたはキーボードのEnter／Spaceで開閉する。
- 原因特定は大きな増加量と実容量前後・Incident減少量比。未特定は参考情報を小さなグレーで区別。A／Cには比率なし。BのL9は前容量・増加量を推測せず、現在容量のみ表示する。
- I05／I06はS14／S15を共有。両Incidentで関連表示するが、当日Scanは16回（定期4、Incident起因12、L2 2／L3 9／L9 5）。比較元の前日Scanは当日の件数に含めない。
- S15は全体が部分取得でもExampleApp対象の正常差分で原因特定。DのS07は対象・比較元の取得失敗を示す。全体partialだけをD扱いしない。
- Scan一覧は実行時刻順。各行を開くと、Incident側と同じ描画関数による対象・前後容量・実行状態・比較元・取得失敗・関連Incidentを表示。正常完了／部分取得／失敗／中止／実行中の例を含む。
- 末尾の「モック確認用」でL1比較元なし／表示日の記録なしを切り替える。通常へ戻すと初期データに戻る。シナリオ切替時は展開状態をリセット、タブ切替時は展開状態を保持する。

## データ根拠と今回の範囲

すべて合成値・架空のパス。日付はブラウザで開いた時点の今日からの相対日付。画面内でのScan取得、DB読み出し、ネットワーク通信、永続化はない。

既存の `blackbox/store.py`、`blackbox/incidents.py`、`docs/storage-incidents.md`、`viewer/App/DatabaseReader.swift` を確認した。

- L1は観測時刻とfree、ScanはID・layer・trigger・targets・options・state・started／ended・error、結果はpath・kind・bytes・status等を保存している。
- Incidentはdetection・evaluation・candidates・investigation・scan_idsを保存。AはL3/L2候補なし、B〜DはL9対象別評価に対応。代表理由の既存優先順はD→B→C。
- L2/L3の候補閾値は検知閾値Tの50%、L9特定は個別の正常差分がT以上。本モックはT=1.00 GiB、候補閾値0.50 GiBの例を使用し、親子の差分を合算しない。
- 明細にない容量・比較元・所要時間は0で補わない。実行中は所要時間を「—」、Bの前容量は「記録なし」。失敗文は合成した短い説明であり、生ログではない。
- 今日のL1の最初と最後の観測による増減例を表示する。実DBでの日付境界・欠測判定・既存読取保護との結合は正式実装時の対象で、今回検証済みとはしない。
